Investigation showed that a Java/Nexus process was already running and legitimately held the `.lock` file.

Current state:

* Java process running
* 8081 listening
* `.lock` owned by the active Nexus process

Therefore, the Ehcache message is considered related to an overlapping/competing startup attempt rather than a current Nexus failure.

**The lock file should not be manually deleted while Nexus is running.**
